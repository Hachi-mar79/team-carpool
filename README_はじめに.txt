# TeamCarpool（チーム配車管理アプリ）

TeamCarpoolは、スポーツチームなどでの送迎・遠征時に、参加者や車両を管理し、自動で配車案を作成できるWebアプリです。

## 1. アプリの利用

**共有版（複数人で利用）**

[https://hachiworks.github.io/team-carpool/shared/](https://hachiworks.github.io/team-carpool/shared/)

- メールアドレスとパスワードで登録・ログインします。
- チームを作成し、ほかのメンバーを招待できます。
- 同じチームのメンバーは、参加者・車両・配車情報を共有できます。
- チームごとの情報は分離され、所属していないチームの情報にはアクセスできない設計です。

## 2. 主な機能

- チームの作成・招待・名称変更
- チームのアーカイブ・復元・削除
- 参加者・車両の登録と編集
- 出欠・車両の使用可否の管理
- 自動配車案の作成
- 配車案の手動調整
- 配車予定の保存・完了・再編集
- 配車履歴の管理
- 複数アカウントでのデータ共有
- 同時編集による上書き防止

## 3. システム構成

| サービス         | 役割              |
| ------------ | --------------- |
| GitHub       | アプリのソースコード管理    |
| GitHub Pages | Webアプリの公開       |
| Supabase     | ログイン認証・共有データの保存 |

共有版の主なソースファイルは `shared/index.html` です。

ルートにある `index.html` は別のローカル保存版です。共有版を更新する際に、誤って上書きしないよう注意してください。

## 4. アプリの更新方法

1. GitHubの `team-carpool` リポジトリを開きます。
2. `shared/index.html` を開きます。
3. 編集する場合は、現在のファイルを事前に保存します。
4. 修正版の内容に置き換えます。
5. **Commit changes** で変更を保存します。
6. 公開URLで動作を確認します。

更新後は、ログイン・参加者の表示・配車予定の保存など、主要機能を確認してください。

## 5. Supabaseの管理

Supabaseでは、次の情報を管理しています。

- ユーザー認証
- チーム情報
- チームメンバー
- 参加者・車両・配車情報
- チームへの招待情報

主なテーブルは以下の4つです。

- `teams`
- `team_members`
- `team_data`
- `team_invitations`

アクセス制限にはRLS（Row Level Security）とデータベース関数を使用しています。

**RLS・関数・アクセス権限は、仕組みを理解せずに変更しないでください。** 設定を誤ると、データへのアクセスができなくなったり、情報が漏えいしたりするおそれがあります。

## 6. 新規登録とメール認証

- メールアドレスの確認（Confirm email）は有効です。
- Supabase標準のメール送信機能を使用しています。
- 現在確認したメール送信上限は1時間あたり2通です。
- 短時間に多数の新規登録やパスワード再設定を行うと、メールを送信できない場合があります。

メール送信に関する制限や仕様は、Supabase側で変更される可能性があります。

## 7. バックアップ

Supabase無料プランでは、プロジェクトの自動バックアップを利用できません。

そのため、必要に応じて手動でバックアップ資料を保存します。

### 保存するデータ

- `teams`
- `team_members`
- `team_data`
- `team_invitations`

### 保存する設定資料

- データベース関数の定義
- RLSポリシー
- RLSの有効状態
- テーブル構造
- テーブルの制約
- 関数の実行権限
- トリガー
- インデックス
- テーブルのアクセス権限

これらは復旧に役立つ資料ですが、**完全なデータベースバックアップではありません。**

Supabase Authのユーザー情報などは別途考慮が必要です。バックアップからの完全復旧は未検証です。

バックアップには個人情報が含まれる可能性があるため、公開GitHubリポジトリには保存せず、アクセス制限のある場所で保管してください。

## 8. 不具合が発生した場合

1. ページを再読み込みします。
2. ログイン状態を確認します。
3. 正しいチームを選択しているか確認します。
4. ほかのメンバーでも同じ問題が起きるか確認します。
5. GitHub PagesとSupabaseの稼働状況を確認します。
6. 必要に応じて、GitHubの更新履歴から直前の変更内容を確認します。

データが表示されない場合でも、原因を確認するまではSupabaseのテーブルやデータを削除しないでください。

## 9. 将来の管理者への引き継ぎ

TeamCarpoolでは、各チームのメンバーがチーム管理や配車を行えます。

ただし、GitHubとSupabaseの管理は別です。

将来、アプリ全体の管理を引き継ぐ場合は、次の事項を確認してください。

- GitHubリポジトリの管理権限
- Supabaseプロジェクトの管理権限
- アプリの公開URL
- バックアップの保管場所
- アプリの更新手順
- Supabaseの無料プランの制限
- 不具合発生時の対応方法

管理者の個人パスワードを共有するのではなく、各サービスが提供する正規の権限付与・移管機能を利用してください。

パスワード、秘密鍵、管理者用APIキーなどは、このREADMEに記載しないでください。

## 10. 旧PWA版について

このリポジトリには、端末ごとにデータを保存する旧PWA版も含まれています。

旧版の基本的な利用方法は以下のとおりです。

1. 必要なファイルをHTTPS対応の静的サイトに配置します。
2. iPhoneのSafariで公開URLを開き、「ホーム画面に追加」を選択します。
3. データは各端末のブラウザ内に保存され、端末間では同期されません。
4. 「データをバックアップ」「バックアップを復元」でデータを管理します。
5. オフライン利用は初回読み込み・キャッシュ完了後に可能です。

**旧PWA版とSupabase共有版は、データの保存・共有方式が異なります。**

旧PWA版は実機未検証のため、まず個人情報を含まないダミーデータで確認してください。

## 11. 運用上の注意

- 無料サービスの利用条件や上限は変更される可能性があります。
- GitHubやSupabaseの管理権限を失うと、アプリの修正・復旧が困難になります。
- 個人情報を含むデータは適切に管理してください。
- 大きな変更を行う前には、バックアップと動作確認を実施してください。
- アプリの運用を完全に無人化できるわけではありません。必要に応じて管理担当者を決めてください。
